# pipeline

약-음식 상호작용 데이터를 공공데이터에서 받아 DB에 넣는 단계. 파이썬, 의존성 없음(표준 라이브러리만).

`apps/api/prisma/seed.ts` 의 상호작용 72행은 손으로 적은 것이고 출처가 없다.
DB에서 `source = 'seed:manual'` 로 표시된다. 이 디렉토리의 목적은 그 행들을
출처가 있는 데이터로 교체하는 것이다.

## 인증키

[공공데이터포털](https://www.data.go.kr) 에서 활용 신청 후 받은 **일반 인증키(Decoding)** 를 환경변수로 넣는다.

```sh
export DATA_GO_KR_KEY='발급받은_키'
```

Encoding 키를 넣으면 `urlencode` 가 한 번 더 인코딩해서 인증 실패한다. Decoding 키를 쓴다.

## 실행

```sh
python3 fetch.py <데이터셋이름> <엔드포인트URL> [추가파라미터=값 ...]
python3 test_fetch.py   # 자체 점검
```

측정은 원본 데이터도 API 키도 없이 돈다 (`eval/*.tsv` 가 문장을 그대로 담는다).

```sh
python3 score.py           # 추출 정밀도/재현율
python3 score.py --risk    # 위험도 정확도 / 격상 정밀도·재현율
python3 score.py --risk-e  # 위험도 오류 (dev 만)
python3 score.py --check   # 하한 미달이면 0 이 아닌 코드로 종료 (CI)
```

받은 원본은 `data/raw/<데이터셋>/<수집시각>/` 에 페이지별로 그대로 저장되고,
같은 디렉토리의 `manifest.json` 에 URL·파라미터(키는 마스킹)·수집시각·페이지별 sha256 이 남는다.

**원본을 고치지 않는다.** 전처리를 수정할 때마다 API를 다시 때리면 재현이 안 되고,
"그때 받은 데이터가 지금과 다르다"를 증명할 수 없다. 원본은 읽기 전용으로 두고 다음 단계가 복사해서 쓴다.

## 확인된 API 계약 (의약품 제품 허가정보)

```
https://apis.data.go.kr/1471000/DrugPrdtPrmsnInfoService08/getDrugPrdtPrmsnDtlInq08
```

실제로 호출해서 확인한 사항이다. 추측이 아니다.

| 항목 | 값 | 비고 |
|---|---|---|
| JSON 플래그 | `type=json` | **`_type=json` 을 보내면 조용히 XML 이 온다** |
| 전체 건수 | 42,713 품목 | 허가일 오름차순(1957년부터) |
| 행 배열 | `body.items` 평면 배열 | `items.item` 중첩이 아니다 |
| 이름 필터 | `item_name=<제품명>` | 부분일치. 탐색에 쓸 수 있다 |
| 한 건 크기 | 약 8~40KB | 주의사항 XML 이 대부분 |

전체를 받으면 약 360MB, `numOfRows=100` 기준 약 430회 호출이다.
개발계정 한도가 1,000회/일이므로 한 번에 받을 수 있지만, 탐색 중에는
`--pages` 로 반드시 끊는다.

### 쓸 만한 필드

| 필드 | 내용 | 용도 |
|---|---|---|
| `ITEM_SEQ` | 품목기준코드 | 기본키 |
| `ITEM_NAME` / `ITEM_ENG_NAME` | 제품명 한/영 | `Drug.nameKo` / `nameEn` |
| `MAIN_ITEM_INGR` | `[M089710]심바스타틴` | `DrugIngredient` (코드+이름) |
| `MAIN_INGR_ENG` | `Simvastatin` | 성분 영문명 |
| `ATC_CODE` | `B05BA03` | `Drug.category` 분류 근거 |
| `ETC_OTC_CODE` | 전문/일반의약품 | |
| `CANCEL_NAME` | 정상 / 취하 | **취하 품목을 걸러야 한다** |
| `NB_DOC_DATA` | 사용상의주의사항 | **약-음식 정보가 여기 있다** |
| `UD_DOC_DATA` | 용법용량 | 복용 시점(식전/식후) |

### 문서 필드 파싱

`*_DOC_DATA` 는 XML 안에 CDATA 로 HTML 이 들어 있는 두 겹 구조다.
`<[^>]*>` 로 한 번에 밀면 `<![CDATA[` 가 본문 첫 `>` 까지 삼켜서 내용이 사라진다
(심바스타틴 품목에서 37,146자 → 618자). `parse.doc_text` 가 두 단계로 벗긴다.
제대로 벗기면 20,716자가 나온다.

### 추출이 실제 과제인 이유

심바스타틴 허가사항에는 이런 문장이 있다.

> 16) 자몽주스: 자몽주스는 CYP3A4를 저해하는 1개 또는 그 이상의 성분을 함유하고 있어
> CYP3A4에 의해 대사되는 약물의 혈장 농도를 증가시킬 수 있다.

기전까지 들어 있는 제대로 된 약-음식 상호작용이다. 그런데 단순 키워드 검색은
오탐이 매우 많다. 같은 문서에서 실제로 걸린 것들:

| 키워드 | 걸린 문맥 | 판정 |
|---|---|---|
| 자몽 | 자몽주스는 CYP3A4를 저해 | **진짜** |
| 술 | 대수**술** 며칠 전과 | 오탐 (수술) |
| 칼슘 | **칼슘**채널차단제 | 오탐 (약물 분류) |
| 공복 | **공복**혈당 ≥5.6mmol/L | 오탐 (검사 수치) |
| 섭취 | 알코올을 **섭취**하였다 | 애매 (음식이지만 상호작용 서술 아님) |

즉 키워드 매칭은 베이스라인이고, 정밀도를 올리는 것이 이 프로젝트의 ML 과제다.
라벨링과 평가셋이 필요한 이유도 이것이다.

## 상호작용 문장 판정: 평가셋과 측정

### 파이프라인

```sh
python3 sample_docs.py     # 성분별 허가사항 표본 수집 -> data/docs.jsonl
python3 make_labelset.py   # 후보 생성 -> eval/candidates.tsv (라벨 칸 비어 있음)
python3 score.py           # eval/labels.tsv 로 지표 측정
python3 score.py --fp      # 남은 오탐 보기 (dev 만)
python3 normalize.py       # 판정된 문장 -> curated/proposals.json (제안)
python3 review.py          # eval/review.tsv 적용 -> curated/interactions.json (적재할 것)
```

`sample_docs.py` 가 성분명으로 조회하는 이유는, 데이터셋 전체가 허가일
오름차순이라 앞 페이지가 1957년 주사액이기 때문이다. 경구약 주의사항이 필요하다.
성분당 1회 호출이므로 개발계정 한도(1,000회/일)에 거의 영향이 없다
(`ROWS_PER_INGREDIENT` 를 20으로 올려도 호출 수는 그대로다).

받은 성분은 건너뛴다. 조건이 "파일이 있으면" 이 아니라 **받은 항목 수 ≥
min(요청 수, totalCount)** 이고 조회어도 함께 본다 (`done_reason`). 파일 유무로만
보면 `ROWS_PER_INGREDIENT` 를 올려도 아무것도 다시 받지 않고, totalCount 를
안 보면 품목이 1개뿐인 성분(리시노프릴)을 실행마다 다시 호출해 할당량을 태운다.

### 두 단계로 나눈 구조

| 단계 | 함수 | 담당 | 방식 |
|---|---|---|---|
| 1 | `extract.candidates` | 재현율 | 음식 사전 71표제어로 문장을 넓게 긁는다 |
| 2 | `extract.judge` | 정밀도 | 차단 사전 + 영향없음 패턴으로 후보를 걸러낸다 |

평가 단위는 **(문장, 음식)** 쌍이다. `Interaction` 이 (성분, 음식) 쌍이기 때문이다.

### 평가셋

세 회차로 모았다. `labels.tsv` 의 `round` 열이 회차다.

| round | 표본 | 문서 | 라벨 | 양성 |
|---|---|---|---|---|
| 1 | 23성분 × 3품목 | 63 | 379 | 147 (38.8%) |
| 2 | 24성분 × 20품목 | 375 | +242 | 88 (36.4%) |
| 3 | 24성분 × 100품목 | 1,479 | +583 | 177 (30.4%) |
| 합계 | | 1,479 | **1,204** | 412 (34.2%) |

- 각 회차는 품목을 늘렸을 때 **새로 나온 문장만**이다. 문서는 23배인데 라벨은
  3.2배다. 제네릭이 같은 주의사항 문구를 그대로 쓰기 때문에 (문장, 음식)
  중복 제거로 대부분 접힌다. 한계 수익이 뚜렷하게 줄고 있다.
- round 3 의 583행 중 **110행은 기존 라벨과 공백·구두점만 다른 재판본**이다.
  라벨을 물려받았고, 그 자체가 표기 변형에 대한 강건성 시험이 된다 (실제로
  `신장(콩 팥)` 처럼 어절 안에 공백이 들어간 행이 차단을 빠져나갔다).
- 앞 회차의 라벨은 **한 줄도 바뀌거나 사라지지 않았다** (키워드 변경 0, 소실 0).
  규칙을 고정한 상태로 다음 회차를 라벨하므로 각 회차는 **처음 보는 제조사 문구에
  대한 홀드아웃**이다. 성분 그룹은 모든 회차에 공통이므로 성분 홀드아웃은 아니다.
- `eval/labels.tsv` 에 문장을 그대로 담았다. **원본 데이터도 API 키도 없이 측정이 재현된다.**

round 2 라벨링 중 round 1 의 라벨 오류 1건을 찾아 고쳤다. `메트포르민 × 설탕`
("저혈당 증상이 인정되는 경우에는 설탕을 투여")이 양성으로 되어 있었는데, 아래
정의가 "음식을 치료 수단으로 쓰는 문장"을 음성으로 두고 같은 문장류인
`글리메피리드 × 설탕`은 음성이었다. 정의가 기준이다. 이 수정으로 기존 발표값
round 1 test 정밀도가 **0.822 → 0.813**, 전체가 0.827 → 0.821 이 되었다.

양성 정의: 그 음식의 섭취가 약의 효과·흡수·안전성을 바꾼다고, 또는 약 때문에
그 음식 섭취를 제한·조정해야 한다고 서술하는 문장.

음성에 포함한 것:

- 키워드가 음식이 아님 (정맥주사, 콩팥, 콜레스티라민, 입술, 유당분해효소)
- 음식이지만 상호작용 서술이 아님 (검사 수치, 질환명, 제제 성분명)
- **상호작용이 "없다"고 명시한 문장** — 허가사항은 병용시험 음성 결과도 적는다. 앱은 위험만 보여주므로 적재 대상이 아니다
- **음식을 치료 수단으로 쓰는 문장** (과량투여 시 제산제 투여, 저혈당에 설탕 섭취)

### round 3: 규칙을 고정한 홀드아웃

round 3 을 라벨하는 동안 **규칙을 한 줄도 고치지 않았다.** 그래서 아래 수치가
"처음 보는 제조사 문구에서의 성능"이다.

| | round 1 | round 2 | **round 3 (고정)** |
|---|---|---|---|
| 추출 정밀도 | 0.821 | 0.863 | **0.768** |
| 추출 재현율 | 1.000 | 1.000 | **0.989** |
| 위험도 정확도 | 0.993 | 0.932 | **0.949** |
| 위험도 과대평가 | 0 | 0 | **0** |
| 위험도 격상 재현율 | 0.941 | 0.684 | **0.526** |

세 가지를 읽을 수 있다.

1. **정밀도는 표본이 커지면 떨어진다.** round 2 의 0.863 은 낙관적이었다.
   문서를 4배로 늘리니 처음 보는 오탐 유형이 나왔다 — 색소명(알루미늄레이크),
   시험 균주(맥주효모균), 첨가제 알레르기(대두유·콩), 광학이성질체 염 이름,
   `공복시험`, `비교용출시험`.
2. **재현율 1.000 이 깨졌다.** 621행까지는 FN 0 이었는데 1,204행에서 2건이 나왔다.
   둘 다 **README 에 미리 적어 둔 한계가 실제로 나온 것**이다 (아래).
3. **위험도의 과대평가 0 은 유지됐다.** 구조 기반으로 바꾼 것이 처음 보는 문구에서도
   작동한다 — 이번 라운드에서 가장 분명한 일반화 증거다. 반면 격상 재현율은
   0.526 으로 떨어졌다. 구조는 일반화했고 **표지 사전은 일반화하지 않았다.**

#### 재현율을 깨뜨린 2건

| 문장 | 막은 규칙 | 미리 적어 뒀는가 |
|---|---|---|
| `고지방 식이와 함께 라베프라졸을 투여시 흡수가 4시간 이상까지 지연될 수 있지만…` | `LEFT_BOUND` (`고지방` 의 `지방` 이 복합어 꼬리로 보인다) | **그렇다.** "`고지방 식사` 처럼 한글이 앞에 붙은 진짜 음식 표현은 같이 죽는다"고 적어 뒀다 |
| `제산제와의 병용투여는 에제티미브의 흡수 속도를 감소시키지만 생체 내 이용률에는 영향을 미치지 않는다` | `_NO_EFFECT` | 아니다. 대조절이 있으면 "영향 없음"이 문장 전체를 뜻하지 않는다는 것을 몰랐다 |

첫 줄이 이 평가셋의 값이다. **한계를 적어 두면 언제 실제로 발생하는지 셀 수 있다.**
`LEFT_BOUND` 를 넣을 때 "이 코퍼스에 그런 양성은 없다"고 썼고, 표본을 4배로 늘리니
1건 나왔다. 재현율 하한을 0.98 로 잡아 둔 것도 그래서 값을 했다 — 1.000 이 아니었다.

### dev / test 분할

**성분 단위**로 나눈다. 문장 단위로 나누면 같은 주의사항 문구를 쓰는 제네릭들
때문에 거의 동일한 문장이 양쪽에 섞여 들어가 test 가 오염된다.
차단 사전과 영향없음 패턴은 **dev 오류만 보고** 고쳤고 test 는 손대지 않았다.

### 결과

| split | n | 양성 | 모델 | 정밀도 | 재현율 | F1 |
|---|---|---|---|---|---|---|
| dev | 525 | 185 | baseline | 0.352 | 1.000 | 0.521 |
| dev | 525 | 185 | **rules** | **0.954** | **1.000** | **0.976** |
| test | 679 | 227 | baseline | 0.334 | 1.000 | 0.501 |
| test | 679 | 227 | **rules** | **0.810** | **0.996** | **0.893** |
| 전체 | 1204 | 412 | baseline | 0.342 | 1.000 | 0.510 |
| 전체 | 1204 | 412 | **rules** | **0.869** | **0.998** | **0.929** |

- 베이스라인(키워드 있으면 양성) 정밀도가 0.34 다. 그냥 쓰면 **의료 정보의 66%가 틀린다.**
- 규칙으로 test 정밀도 0.334 → 0.810.
- **재현율이 1.000 이 아니다.** 1,204행에서 FN 1건(test) 이 남았다 — 위 "재현율을
  깨뜨린 2건" 중 `고지방 식이` 쪽이고, 일부러 고치지 않았다 (아래 "남은 한계").

`score.py --check` 가 하한(정밀도 0.82 / 재현율 0.98)을 지킨다. CI 에서 돌아간다.

#### 표본을 6배로 늘렸을 때: 처음 보는 문구에서의 일반화

round 2 는 규칙을 고정한 뒤에 라벨했다. 그 상태의 측정값이 유일하게 깨끗한
일반화 수치다.

| | round 1 (규칙을 만든 데이터) | round 2 (처음 보는 문구) |
|---|---|---|
| 규칙 고정 상태 정밀도 | 0.821 | **0.786** |
| r2 dev / r2 test | — | 0.943 / **0.714** |

**정밀도가 떨어졌다.** 떨어진 오탐이 전부 사전에 없는 복합어였다 —
`관상동맥회로우회술`, `혈장분리반출술`, `스칸디나비아지방`, `칼슘 antagonist`.
복합어를 하나씩 적는 차단 사전은 처음 보는 복합어에 그대로 뚫린다는 뜻이다.

근본 원인은 "복합어 목록"이라는 방식 자체였다. 차단해야 했던 `술` 복합어
22개가 **전부 앞에 한글이 붙은 형태**였고, 음식으로 쓸 때는 항상 어절 머리에
온다("술을 마시는"). 목록을 지우고 어절 경계 한 줄로 바꿨다 (`extract.LEFT_BOUND`).
`지방`도 같다 (중성지방·체지방·고지방혈증은 앞에 붙고, "…, 지방, 야채류 섭취"는
어절 머리다).

| | round 1 | round 2 | r2 test | 차단 복합어 수 |
|---|---|---|---|---|
| 복합어 목록 | 0.821 | 0.786 | 0.714 | 84 |
| **어절 경계 + 동등성시험 제외** | **0.821** | **0.863** | **0.797** | **57** |

- round 1 수치가 **소수점까지 그대로다** (FP 32건 동일). 경계 규칙이 기존 차단
  목록과 동작이 같고, 목록에 없던 복합어만 추가로 잡는다는 뜻이다. 사전은 84 → 57 로 줄었다.
- r2 test 가 0.714 → 0.797. **test 오탐을 보지 않고 고쳤는데 test 가 같이 올랐다.**
  고친 근거는 dev 오탐(`스칸디나비아지방`, 동등성시험 문장)뿐이다.
- 남은 r2 test 오탐 14건에는 `칼슘 antagonist` / `칼슘 amtagonist`(원문 오타)가 있다.
  test 분할(암로디핀)에만 나타나므로 **일부러 고치지 않았다.** 고치면 test 가 거짓이 된다.

round 2 에서 새로 드러난 문장 유형이 하나 더 있다. **생물학적 동등성 시험 보고**다.
"건강한 성인에게 **공복 시** 단회 경구투여하여 … 비교평가항목치(AUCt, Cmax)를
로그변환하여…" 형태로, 공복은 시험 조건일 뿐 상호작용이 아니다. 품목을 20개씩
받으니 제네릭마다 자기 동등성 시험 결과가 붙어서 이 부류가 한꺼번에 늘었다.
`extract._BIOEQ` 로 문장 단위로 제외한다.

### 남은 한계

1. **재현율의 상한.** 재현율 1.000은 1단계가 만든 후보 풀 안에서의 값이다.
   음식 사전에 전혀 걸리지 않는 문장은 측정 범위 밖이다. 문서 전체를 라벨링해야
   실제 재현율이 나온다.
2. **남은 오탐 31건은 거의 전부 "음식을 치료 수단으로 쓰는 문장"** 이다.
   규칙으로 쓰면 브리틀해진다. 여기부터가 분류 모델의 몫이다.
3. **라벨러가 1명이고, 규칙을 쓴 사람과 같다.** 라벨은 규칙보다 먼저 붙였지만
   편향이 없다고 할 수는 없다.
4. **원본 데이터에 오타가 있다.** test 오탐 중 `칼슘체널저해제`(채널→체널),
   `칼슘 amtagonist`(antagonist)가 있다. test 를 보고 사전에 넣으면 측정이
   거짓이 되므로 넣지 않았다.
5. 표본이 **24개 성분**이다. 성분 수는 seed 의 약품에 묶여 있다. 전체 42,713품목으로
   넓히면 사전에 없는 음식이 나온다.
6. **round 2 는 성분 홀드아웃이 아니다.** 성분 그룹이 round 1 과 같고 문구만 새롭다.
   그리고 round 2 를 라벨하면서 test 문장도 전부 읽었으므로, 어절 경계 수정 이후의
   r2 test 0.797 은 완전히 깨끗한 홀드아웃이 아니다. 깨끗한 수치는 규칙 고정 상태의
   **0.714** 다. 다음 회차(round 3)가 이 수정의 깨끗한 검증이 된다.
7. `LEFT_BOUND` 는 "고지방 식사"처럼 앞에 한글이 붙은 **진짜** 음식 표현을 같이
   죽인다. 이 코퍼스에 그런 양성은 없었지만(고지방 2건 전부 고지방혈증) 나오면
   그 표제어를 `FOODS` 에 따로 넣어야 한다.

## 위험도 규칙 측정

배지(`금기` / `경고` / `주의`)는 `normalize.risk_level` 이 매긴다. 규칙 기반인데
정확도를 재지 않고 있었다. 추출은 재는데 **사용자가 보는 색은 안 재고 있었다.**

### 무엇을 재는가

라벨 단위는 `(문장, 키워드)` 다. 재는 것은 임상적 진실이 아니라 **그 문장이 그 음식에
대해 지시하는 행동 수준**이다. 사용자에게 이 문장이 그대로 보이고 배지가 그 위에 붙으니,
배지는 문장과 맞아야 한다. 허가사항이 느슨하게 쓴 것은 느슨한 대로 라벨한다.

판정 기준은 `eval/RISK_RUBRIC.md` 에 있고 **문장을 읽기 전에 고정했다.** 문장을 보고
기준을 만들면 측정값이 사후합리화가 된다. 경계 사례 7개를 미리 정했다 — 교차참조,
금지 대상이 그 음식이 아닌 경우, 간격 두기, 공복 복용 지시, 동률일 때 낮은 쪽 등.

모집단은 `labels.tsv` 의 **양성 235건**이다. 음성 문장의 위험도는 뜻이 없다.
`risk` 열을 추가했다.

| 라벨 | round 1+2 | **전체 (round 3 포함)** | 비율 |
|---|---|---|---|
| `caution` | 199 | **357** | 86.7% |
| `warning` | 33 | **51** | 12.4% |
| `contraindicated` | 3 | **4** | 1.0% |

**다수 클래스가 86.7% 다.** 전부 `caution` 이라고 답해도 정확도 0.867 이 나오므로
정확도만으로는 아무것도 못 본다. 그래서 **격상 정밀도/재현율**을 따로 본다 —
`caution` 위로 올린 것이 맞았는가, 올려야 할 것을 올렸는가. 배지가 사용자 행동을
바꾸는 지점이 거기다.

### 라벨링 절차

235건을 공백·구두점을 무시해 묶으면 **160개 문장군**이다(제네릭이 같은 주의사항을
표기만 바꿔 쓴다). 군 단위로 읽었다.

1. 규칙이 격상한 **20군**은 전문을 읽고 판정했다.
2. 규칙이 `caution` 이라고 한 **140군**은 `RISK_RULES` 보다 넓은 지시어 목록
   (피하/피해/않도록/말 것/금기/삼가/중지/권고되지/바람직/제한/중단/금지/주의/…)
   으로 갈라, 걸린 **26군**을 전문을 읽고 판정했다.
3. 아무것도 안 걸린 **114군**은 더 넓은 목록(말아/마십시오/않아야/자제/권장하지/
   신중/…)으로 한 번 더 걸러 **8군**이 나왔고, 전문을 읽어 전부 `caution` 임을 확인했다.
   나머지 106군은 지시어가 한 글자도 없는 기전 서술이다.

3단계가 이 절차의 검산이다. 없으면 "규칙이 caution 이라고 한 것은 caution 이겠지"로
라벨이 규칙을 따라가 버린다.

### 고친 것 (dev 오류 7건만 보고)

1. **교차참조를 금기로 읽었다.** `"(… 투여하지 말 것 항 참조)"` 안의 금지 문구가
   걸려서, 기전만 설명하는 문장에 금기 배지가 붙었다. 괄호 안에 `참조` 가 있으면
   지우고 판정한다. 먼저 지우므로 참조 문구가 창을 잡아먹지도 않는다.
2. **`"병용투여를 피한다"` 가 금기 쪽에 있었다.** 회피 권고와 금지는 다르다.
   `warning` 의 `"피한다"` 가 이미 받으므로 **지워서** 고쳤다.
3. **`"권장하지 않"` 이 표지에 없었다.** `"권고되지 않"` 과 같은 뜻인데 조사만 다르다.
   암로디핀 자몽의 `"병용투여를 권장하지 않는다"` 4건이 전부 `caution` 이었다.
4. **`RISK_WINDOW` 80 → 120.** dev 를 쓸어 보니 100~140 이 평탄하고(정확도 0.946)
   160 부터 과대평가가 3 → 7 로 튄다. 두 절벽에서 가장 먼 값을 골랐다.

### 글자 거리를 구조로 바꿨다

`RISK_WINDOW` 를 **지웠다.** 대신 세 가지로 가린다.

#### 1. 괄호 소속 — 방향이 있는 규칙이다

괄호는 **종속 범위**다. 바깥 지시어는 괄호 안으로 내려가지만, 괄호 안 지시어는 밖으로
나오지 못한다. 이 방향성이 핵심이다. 대칭으로 만들면 둘 중 하나가 깨진다.

| 문장 | 키워드 | 지시어 | 적용? |
|---|---|---|---|
| `간 기능장애(… 이 약의 투여를 피해야 한다.), 폐경색, …, 과도한 알코올 섭취자` | 알코올 (밖) | 괄호 안 | ✗ 간 기능장애의 것이다 |
| `유제품 또는 무기질 강화음료(예, 우유, 요구르트)와 … 병용하지 않는 것이 바람직하다` | 우유 (안) | 괄호 밖 | ✓ 문장 전체의 지시다 |

구현은 각 문자의 **괄호 중첩 경로**(여는 괄호 위치의 튜플)를 만들고, 지시어의 경로가
키워드의 경로의 **접두어**인지 본다. 접두어면 지시어의 범위가 키워드를 품는다는 뜻이다.
형제 괄호끼리는 서로 접두어가 아니므로 자동으로 막힌다.

#### 2. 불릿 경계를 넘지 않는다

`- 공복 또는 영양실조 - 간장애 음주 및 알코올이 포함되어 있는 약물의 복용을 피해야 한다`
에서 `공복` 은 다른 항목이다. 구분자 앞에 공백을 요구한다 — `1-2시간`,
`70 mg/2800 IU`, `급ㆍ만성적` 을 불릿으로 읽으면 문장이 조각난다.

#### 3. 복용 간격 지시는 용법이다

`이 약 투여 전 1 ～ 2시간 및 투여 후 4시간 이내에는 병용하지 않는 것이 바람직하다`
는 금지가 아니라 **언제 먹으라는 지시**다. `RISK_RUBRIC.md` 경계 사례 4 로 미리 정해
둔 것이고, 시프로플록사신 제산제 문장 **12행이 여기 걸린다(전부 dev)**. 지시어 바로
앞에 시간 표현이 있으면 그 지시어를 세지 않는다.

같은 문구인데 간격 지시가 없으면 경고다. 둘을 가르는 것이 간격 표현이다.

```
칼슘 … 투여 전 1～2시간 및 투여 후 4시간 이내에는 병용하지 않는 것이 바람직하다  -> 주의
칼슘 함유 제제와 이 약은 병용하지 않는 것이 바람직하다                          -> 경고
```

#### 창을 지울 수 있다는 근거

세 규칙을 넣은 뒤 창을 다시 쓸었다. **dev 가 모든 값에서 1.000 이다.**

| window | 120 | 160 | 200 | 300 | 500 | ∞ |
|---|---|---|---|---|---|---|
| dev 정확도 | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 | **1.000** |
| test 과대 | 0 | 0 | 0 | 0 | 0 | **0** |

세인트존스워트, 121자 건, 올바른 방향). 거리는 구조와 간격 규칙이 들어오면 더 이상
아무 일도 하지 않는다. 그래서 **지웠다** — 지우면 121 대 120 같은 눈금 문제가
질문 자체로 사라진다.

#### 이 test 숫자는 일반화의 증거가 아니다

고쳐진 test 오류 5건이 **1차 결과에 열거해 둔 12건 중 5건과 정확히 일치한다**
(괄호 3, 불릿 1, 거리 121자 1). 새로 생긴 오류 0건, **내가 모르던 행에서 부수적으로
고쳐진 것 0건**. 즉 test 는 "알고 있던 것을 고쳤다"만 보여준다. 홀드아웃을 썼다.

정당성의 근거는 test 숫자가 아니라 셋이다.

1. **dev 1.000 이 유지된다.** 93행에서 퇴행이 없다.
2. **구조가 dev 에서 관측된다.** 괄호 소속 어긋남이 dev 2행, 간격 표현이 dev 12행에
   있다. 지금은 창 거리가 우연히 막아주고 있었을 뿐이다 — 맞지만 이유가 틀린 상태였다.
3. **위치 기반으로 다시 쓴 코드가 구조를 끄면 기존 규칙과 완전히 일치한다**
   (dev 1.000/0/0, test 0.915/4/8). 재작성 자체가 동작을 바꾸지 않았다는 증거다.

낙관적으로 나왔던 것**이다. 그래서 CI 하한을 0.76 에서 **0.70 으로 내렸다.**

dev 에는 한 건도 안 나왔다. 표지 한 줄이면 고쳐지지만 **고치지 않았다.**
test 전용 형태를 계속 고치면 test 숫자가 의미를 잃는다.

지난 라운드에 같이 적어 둔 `"피 해야"`(어절 내 공백)는 **고쳐졌다.** 이번 round 3
dev 오탐(`신장(콩 팥)`)에서 출발한 공백 허용 매칭에 함께 걸렸다. test 전용 결함을
dev 신호로 고친 사례다 — 기다린 값이 있었다.

### 한계

- **금기 라벨이 4건이다.** 라벨을 412건까지 늘렸는데도 4건이고, **4건 전부 test
  분할**이라 dev 에는 금기 라벨이 하나도 없다. 3건을 맞혔다고 해서 금기 판정이
  믿을 만하다고 말할 수 없다. 놓친 1건은 round 3 의 `"과량의 알코올과 병용투여
  하지 않는다"` 다 — 표지에 `병용하지 않는다` 는 있는데 `투여` 가 끼어든 형태가 없다.
  dev 신호가 없어 고치지 않았다.
- **플루옥세틴 × 세인트존스워트는 임상적으로 중대한 상호작용인데 `주의` 로 내려갔다.**
  근거 3건이 전부 "위험성을 인식해야 한다" 수준의 서술문이라 더 강한 문장이 풀에 없다.
  배지를 올리면 **보여주는 문장과 어긋난다** — 지난번에 고친 버그가 그것이다.
  문장에 맞추는 쪽을 택했다. 허가사항 문구가 약한 것을 규칙으로 메울 수는 없다.
- **같은 상호작용인데 성분마다 배지가 다르다.** 플루옥세틴 × 세인트존스워트는
  `주의`, 서트랄린 × 세인트존스워트는 `금기` 다. 둘 다 세로토닌 증후군인데
  식약처 허가사항의 문구 강도가 다르다(앞은 "인식해야 한다", 뒤는 "금기해야 한다").
  출처 문장을 그대로 보여주는 설계의 직접적 결과다. 문구를 규칙으로 메우면
  출처 없는 판단이 섞인다.
- **창을 지운 대가.** 괄호도 불릿도 없는 **평평한 긴 나열**에서 멀리 있는 지시어가
  올라올 수 있다. 이 코퍼스에는 그런 형태가 없다(후보 272건 중 0건)지만, 나오면
  거리로 돌아가는 게 아니라 절 경계를 봐야 한다.
- 라벨은 한 사람(나)이 매겼다. 교차 검증이 없으니 경계 사례의 일관성은
  `RISK_RUBRIC.md` 를 먼저 쓴 것에 의존한다.

`score.py --check` 가 셋을 지킨다. 측정값보다 낮게 잡아서 실제 퇴행만 걸리게 한다.

|---|---|---|
| 정확도 | 0.966 | 0.95 |
| 격상 정밀도 | 1.000 | 0.95 |

격상 정밀도가 1.000 이지만 하한을 1.00 으로 두면 오탐 하나에 CI 가 죽는다.
과대평가 0 인 성질은 지키고 싶으니 0.95 로 뒀다.

격상 재현율 하한은 **내렸다.** 라벨 235건에서 0.778 이던 값이 412건에서 0.745 다.
하한을 내리는 건 보기 나쁘지만, 측정값보다 높은 하한은 CI 를 거짓으로 죽인다.
하한은 "지키고 싶은 값"이 아니라 "지금 지켜지는 값"이어야 한다.

정확도를 함께 두는 이유는, 금기와 경고를 혼동하는 경우를 격상 지표가 둘 다
"격상"으로 세어 놓치기 때문이다.

### 왜 사람이 확인하는가

추출 정밀도가 0.836 이다. 91건을 그대로 적재하면 **의료 정보 약 15건이 틀린다.**
자동 추출은 제안까지만 하고, `eval/review.tsv` 의 판정을 거친 것만 적재한다.
판정 없는 제안이 있으면 `review.py` 가 에러로 멈춘다 — 새 데이터를 받았을 때
리뷰되지 않은 행이 조용히 적재되는 것을 막는다.

이게 측정의 실질적 가치다. 베이스라인으로 제안을 만들면 리뷰할 양이
91/0.378 ≈ 241건이다. 규칙을 거치면 91건이다. **리뷰 부담이 62% 줄었다.**

| | 건수 |
|---|---|
| 제안 | 91 |
| 승인 | 76 (84%) |
| 거부 | 15 |

### 판정 기준

두 가지를 모두 만족해야 `ok` 다.

1. 그 (성분, 음식) 쌍이 실제 상호작용인가
2. **대표 문장이 그것을 뒷받침하는가** — 이 문장이 사용자에게 그대로 보인다

2번만 틀린 경우(쌍은 맞는데 문장이 엉뚱한 경우)는 거부하지 않고 `pick` 으로
근거를 교체한다. 거부하면 알렌드로네이트-음식처럼 임상적으로 가장 중요한
상호작용을 잃는다(공복 복용).

### pick 은 ok 행에 필수다

`review.tsv` 를 (성분, 음식) 으로만 키를 잡으면 근거 선택 규칙을 고쳤을 때
승인이 조용히 다른 문장에 따라붙는다. 실제로 그랬다 — 랭킹을 밀도 기준으로
바꾼 뒤 메트포르민-음식의 근거가 "수술 과정의 경우에(음식과 수액의 섭취에
제한이 없는...)" 로 바뀌었고, 승인은 그대로 남아 있었다. 그래서 `pick` 에
승인한 문장의 접두어를 적어 고정한다. 일치하는 근거가 없으면 에러다.
접두어는 그 쌍 안에서 유일해지는 최단 길이로 잡았다.

표본을 성분당 3 → 20품목으로 늘렸을 때 **승인 77건 중 21건의 `pick` 이 여러
문장에 걸렸다.** 핀 장치가 조용히 다른 문장을 쓰는 대신 멈췄다 — 의도한 동작이다.
다만 21건 중 대부분은 제조사별 **띄어쓰기·구두점 차이**뿐이었다
("투여시"/"투여 시", "(예, 우유"/"(예 : 우유", "미치게"/"미 치게").
이런 변형은 같은 문장이므로 공백·구두점을 지운 뒤 비교해서 같으면 통과시킨다
(`review.same_text`). 내용이 다르면 그대로 멈춘다. 실제로 내용이 다른 것은
6건이었고(`약용탄`/`활성탄`, `혈장`/`혈중`, "(단, 경구용 제제에 한함)" 추가 등)
접두어를 늘려 하나만 고르게 했다.

적재 결과를 기존 적재물과 대조해 확인했다: 근거 문장 **완전 동일 72건 /
공백·구두점만 다름 1건 / 내용 다름 0건**. 승인한 문장이 그대로 유지됐다.

#### round 3 에서 핀을 늘릴 때 실수했다

품목을 20 → 100 으로 늘리니 **8건의 `pick` 이 내용이 다른 문장에 걸렸다.**
처음에는 "충돌하면 1순위 근거로 접두어를 늘린다"로 자동 처리했는데, 그러면
**승인했던 내용이 바뀐다.** 세티리진 × 알코올이 `"과량의 알코올과 함께 투여하지
않는다"` 에서 `"과량의 알코올과 병용투여 하지 않는다"` 로 옮겨갔고, 뒤쪽 문구는
금기 표지에 없어서 배지가 `금기` → `주의` 로 **내려갔다.**

적재 결과를 직전 적재물과 대조해서 잡았다. 고친 방법은 접두어를 늘릴 때 **직전에
적재돼 있던 문장**(= 승인된 내용)을 목표로 삼는 것이다. 8건 전부 내용이 유지됐고
금기 2건이 복원됐다.

핀 장치는 제 역할을 했다(멈췄다). 틀린 건 자동 복구 쪽이었고, **적재물 대조**가
그걸 잡았다. 자동으로 고칠 때는 "무엇을 보존해야 하는지"를 먼저 정해야 한다.

### 근거 문장 고르기

한 (성분, 음식) 쌍에 여러 품목의 문장이 모인다. 순서는 이렇다.

1. 위험도 높은 것. 약한 문구를 골라 위험을 낮춰 보여주면 안 된다.
2. 기전·결과 표현의 **밀도**가 높은 것.
3. 긴 것. 밀도가 같으면 맥락이 더 있는 쪽.

개수가 아니라 밀도인 이유는, 약물을 수백 자 나열한 문장도 개수로는 높게
나오기 때문이다(로수바스타틴 제산제에서 실제로 그랬다). 길이 내림차순만
쓰면 그 나열 문장이, 키워드 위치만 쓰면 "9) 알코올을 복용한 사람" 같은
토막이 뽑힌다. 셋 다 실제로 겪은 뒤에 정한 순서다.

위험도는 문장 전체가 아니라 **키워드 주변 80자**만 보고 매긴다. 전체를 보면
음식과 무관한 경고어가 위험도를 올린다 — 메트포르민 알코올이 "간질환
환자에게는 투여를 피해야 한다"의 "피해야" 때문에 warning 으로 올라갔다.

### riskLevel 은 보여줄 문장에서 다시 계산한다

`normalize.py` 의 `riskLevel` 은 순위 1위 문장 기준이다. 그런데 리뷰에서 `pick`
으로 다른 문장을 고르면 **배지와 설명이 어긋난다.** 표본 확대 후 확인해 보니
적재 77행 중 **9행이 어긋나 있었다** — `caution` 문장에 `warning` 배지가 붙고,
그 반대도 있었다. 승인이 다른 문장에 따라붙던 버그와 같은 계열이다.

원인은 `evidence` 가 문장만 담고 있어서, 교체한 문장의 키워드를 알 수 없다는
것이었다(위험도는 키워드에 걸리는 지시어로 매긴다). `evidence` 를
`[문장, 키워드]` 쌍으로 바꾸고 `review.py` 가 고른 문장에서 위험도를 다시 계산한다.
불변식은 `riskLevel == risk_level(reasonKo, keyword)` 이고 적재 행 전부 만족한다.

`Interaction.reasonEn`, `sideEffectsKo`, `sideEffectsEn` 을 nullable 로 바꿨다

### Food 모델 중복 정리

같은 음식을 여러 Food 행으로 쪼개 둔 것이 원인이었다. 사용자에게 보이는
버그였다 — **타이레놀을 조회하면 알코올 항목이 4개 나오고 위험도가 서로 달랐다**
(소주 `contraindicated` / 알코올 `caution` / 맥주 `contraindicated` /
와인 `contraindicated`).

기계적으로 묶으면 틀린다. 행을 하나씩 읽고 판단했다.

| 계열 | 판정 |
|---|---|
| `알코올 (맥주)`·`(와인)`·`소주` → `알코올` | 중복 **15건**. 본문이 "맥주"가 아니라 "알코올"이라고 적혀 있다 ("알코올이 메트포르민과 병용 시 젖산 산증") |
| `알로푸리놀 × 알코올 (맥주)` | **중복 아니다.** "맥주에 포함된 **푸린**이 요산 수치를 상승"이라 에탄올과 다른 기전이다. Food 이름을 `맥주` 로 바꿔 남겼다 |
| `알로푸리놀 × 소주`, `에소메프라졸 × 알코올 (맥주)` | 에탄올 기전인데 출처 있는 알코올 행이 없다. 음식만 `알코올` 로 **옮겼다** |
| `자몽주스` → `자몽` | 중복 **2건**. 아토르바스타틴은 거의 같은 문장이 **출처 있는 행으로 양쪽에 하나씩** 있었다 — 파이프라인이 만든 중복이다 |
| `철분보충제` → `철분` | 중복 1건 + 이동 1건 |
| `우유 (저지방)` | 0행이고 `우유` 와 중복 |
| `우유`/`요거트`, `커피`/`녹차`/`에너지드링크` | **중복 아니다.** 사용자가 구분해서 먹는 음식이고 기전만 같다. 유지 |

결과: 손으로 적은 상호작용 72 → 53행, Food 46 → 41개, 적재 후 합계 137 → 118행.

#### 왜 이런 중복이 생겼나 — 세 가지 구조 문제

1. **`Food.nameKo` 에 유니크 제약이 없었다.** 적재 스크립트가 이름으로 찾아본 뒤
   없으면 만드는 구조였는데, seed 가 `알코올` 을 안정적인 id 로 넣기 시작하자
   파이프라인이 과거에 uuid 로 만든 행과 겹쳤다. **`알코올` Food 가 두 행
   (21행 / 19행)으로 쪼개져 앱이 알코올을 두 번 보여줬다.** 이름이 Food 의 사실상
   식별자이므로 DB 가 지켜야 한다 → 마이그레이션 `0005_food_name_unique` 가
   기존 중복을 합친 뒤 제약을 건다. 적재 스크립트는 `upsert` 로 단순해졌다.
2. **seed 가 Food 어휘의 주인이 아니었다.** `알코올`·`철분` 을 파이프라인이
   만들었고 CI 순서가 seed → load 라서, seed 행이 그 Food 를 참조할 수 없었다.
   (그래서 `알로푸리놀 × 알코올` 같은 행을 손으로 적을 수 없었다.)
   파이프라인이 쓰는 음식 10개를 seed 로 옮겼다(`f037`–`f046`).
   파이프라인은 여전히 없는 음식을 만들 수 있고, 그때 찍히는 "새 Food N개"가
   사전에 없던 음식이 나왔다는 신호가 된다.
3. **seed 가 지운 행을 회수하지 못했다.** `upsert` 만 하므로 배열에서 지운 행이
   기존 DB 에 그대로 남는다. 중복이라 지운 맥주 9행이 실제로 남아 있었다.
   **CI 는 매번 빈 DB 라 통과하고 오래된 DB 만 틀리는 종류의 문제다.**
   `source = 'seed:manual'` 은 "seed.ts 가 적은 행"이라는 뜻이므로 그 집합은
   배열이 정의한다. 배열에 없는 manual 행을 지운다 (출처 있는 행은 건드리지 않는다).

#### 재발 방지

`prisma db seed` 가 시작할 때 멈춘다. 셋 다 실제로 걸리는 것을 확인했다.

- `FOODS` 에 이름이 겹치는 항목이 있으면
- 은퇴시킨 이름(`소주`, `자몽주스` 등)을 다시 넣으면
- `INTERACTIONS` 가 `FOODS` 에 없는 `foodId` 를 가리키면

#### 남은 한계

- **위험도가 내려간 쌍이 있다.** 손으로 적은 행이 `contraindicated` 였고 출처 있는
  행이 `caution` 인 경우(아세트아미노펜 × 알코올 등), 중복을 지우면 표시 위험도가
  내려간다. 두 값의 최대치를 쓰는 쪽이 안전해 보이지만, 그러면 배지가 **보여주는
  문장과 어긋난다** — 방금 고친 버그가 그것이다. 출처 있는 원문을 그대로 보여주는
  쪽을 택했다. 그 뒤에 `riskLevel` 규칙을 측정했다 (위 "위험도 규칙 측정" 절).
  측정 결과 이 규칙은 과대평가보다 **과소평가**가 많았다 — 최대치를 쓰는 쪽이
  안전해 보였던 직관과 방향이 다르다.
- 복합제 허가사항이 다른 성분의 문장을 섞던 문제는 아래 "복합제 성분 귀속"에서
  고쳤다.

### 복합제 성분 귀속

`item_name` 부분일치로 조회하면 복합제도 걸린다. 복합제 허가사항은 두 성분의
주의사항이 **한 문서**에 들어 있는데, 문서를 조회어에 통째로 귀속시키면 다른
성분의 문장이 그 성분의 근거로 올라온다. 실제로 1순위 근거였던 것들이다.

| 쌍 | 올라온 문장 | 실제 주체 |
|---|---|---|
| 아토르바스타틴 × 자몽 | "따라서, **암로디핀**은 자몽이나 자몽주스와 병용시 … 병용투여를 권장하지 않는다" | 암로디핀 (카듀엣) |
| 미노사이클린 × 알코올 | "경구 **메트로니다졸**을 알코올과 병용시 디설피람양 작용으로 antabuse 효과…" | 메트로니다졸 (페리메디 치과용 연고) |
| 아세틸살리실산 × 식이섬유 | "차이니즈 햄스터 **섬유**아세포를 대상으로 한 유전자 돌연변이 시험 … **클로피도그렐**에 의한 유전독성은 나타나지 않았다" | 클로피도그렐 |

#### 측정

`MAIN_ITEM_INGR` 로 성분을 읽고, 복합제 문서의 문장 중 **다른 성분을 이름으로
부르면서 조회 성분은 부르지 않는 것**만 버린다.

| | 값 |
|---|---|
| 복합제 문서 | 375건 중 **10건** |
| 그 문서들의 판정된 후보 | 70건 |
| 그중 다른 성분의 문장 | **11건 (15.7%)** |
| 전체 판정된 후보 2,107건 기준 | 0.52% |
| 제안 | 91 → **90건** (아세틸살리실산 × 식이섬유 소멸) |
| 적재 | 76 → **76건 (변화 없음)** |

적재 행이 하나도 바뀌지 않은 것이 이 수정의 정확한 값이다. 세 건 중 두 건은
`pick` 이 이미 다른 문장으로 고정해 둬서 사용자에게는 보이지 않았고, 한 건은
사람이 `no` 로 거부해 둔 상태였다. 즉 **사람 리뷰가 세 건 전부 잡아냈다.** 바뀐
것은 (1) 거부 1건이 제안 단계에서 사라져 리뷰 부담이 줄고, (2) 미노사이클린 ×
알코올의 `itemSeqs` 에서 치과용 연고 품목(`202601108`)이 빠져 **출처가 정확해진
것**이다. 틀린 출처는 되짚을 때 드러나지 않는 종류의 오류다.

#### 문서를 버리지 않은 이유

복합제 문서 10건을 통째로 제외하는 쪽이 한 줄이지만, 그러면 **제안 83건**이 되고
알렌드로네이트 7건이 전부 사라진다. 국내 허가 품목이 복합제 1건(알렌드론산 +
콜레칼시페롤)뿐이어서다. 거기에는 이 데이터셋에서 임상적으로 가장 중요한
"복용 후 30분간 눕지 말고 물과 함께 공복에" 가 들어 있다. 그래서 문장 단위로 가른다.

둘 다 부르지 않는 문장("이 약은 …")은 **남긴다.** 복합제 전체에 대한 서술이고,
알렌드로네이트의 공복 복용이 바로 그 형태다.

#### 염·수화물 접미어는 사전 없이 맞춘다

`MAIN_ITEM_INGR` 는 표준명(`암로디핀베실산염`, `메트로니다졸벤조산염`)이지만 문장은
기본명(`암로디핀`, `메트로니다졸`)을 쓴다. 접미어 사전(염산염/황산염/수화물/…)을
적는 대신 **앞 네 글자**로 맞춘다. 접미어는 뒤에만 붙으므로 접두어는 그대로 남고,
새 복합제가 나올 때마다 사전을 늘릴 필요가 없다.

처음에는 "문서 전체에서 찾을 수 있는 가장 긴 접두어"를 썼는데 **틀렸다.** 허가사항
머리글에는 표준명 전체가 적혀 있어서 `메트로니다졸벤조산염`이 잡히고, 문장의
`메트로니다졸`과 맞지 않아 미노사이클린 × 알코올이 그대로 통과했다. 가장 긴 이름은
가장 안 쓰이는 이름이다.

조회어가 `MAIN_ITEM_INGR` 어디에도 없으면 어느 쪽이 "이 약"인지 알 수 없으므로
**멈춘다**(`MAIN_INGR_ALIAS` 에 표준명 추가를 요구한다). 실제로 알렌드로네이트가
걸린다 — 표준명이 `알렌드론산`이다. 조용히 넘기면 그 문서의 두 성분을 모두
"다른 성분"으로 보고 근거를 전부 버린다.

**round 3 에서 이 가드가 실제로 걸렸다.** 텔미누보정(텔미사르탄 + **에스**암로디핀
베실산염이수화물)에서 조회어 `암로디핀` 을 찾지 못해 멈췄다. 광학이성질체는 접두어가
붙는다(에스암로디핀, 레보세티리진). 같은 활성 부분이라 상호작용 기전이 같으므로
접두어 일치(`startswith`)를 **부분문자열 일치로 바꿨다.** 가드가 없었으면 텔미누보
문서의 두 성분을 모두 "다른 성분"으로 보고 암로디핀 근거를 조용히 버렸을 것이다.

#### 측정값에 영향이 없는 이유

`eval/labels.tsv` 는 **문장 단위 판정**("이 문장이 상호작용 서술인가")이고, 귀속은
그 하류다. 암로디핀 자몽 문장은 **진짜 상호작용 서술**이다 — 성분이 다를 뿐이다.
그래서 정밀도 0.836 / 재현율 1.000 은 그대로이고, 그대로인 것이 맞다. 라벨 621건도
무효가 되지 않는다(`FOOD_ALIAS` 를 `extract` 가 아니라 `normalize` 에 둔 것과 같은 이유).

귀속 정확도는 아직 평가셋이 없다. 위의 15.7% 는 규칙이 바꾼 양이지 규칙의 정확도가
아니다. 복합제 문서가 10건뿐이어서 전수 확인이 가능했고, 11건 전부 눈으로 봤다.

#### 고치지 않은 것

`아세틸살리실산 × 식이섬유`의 판정 메모는 두 가지를 지적하고 있었다. 하나는 귀속
(클로피도그렐 문장)이고 다른 하나는 **`섬유아세포`가 차단 사전에 없는 복합어**라는
것이다. 뒤쪽은 고치지 않았다 — 그 문장은 **test 분할**(아스피린)에만 있어서, 보고
고치면 test 숫자가 거짓이 된다. `섬유` 라벨 8건은 전부 음성이고 오탐은 이 1건이다.

### 거부한 20건

round 3 에서 제안이 90 → 96 건이 됐다. 새 제안 9건은 **전부 거부**다 — 평가셋에서
내가 이미 음성으로 라벨한 오탐이고, test 분할 전용 형태라 규칙으로 고치지 않은
것들이다. 동시에 기존 거부 3건(글리메피리드 × 과일주스·설탕, 메트포르민 × 엽산)은
새 규칙이 제안 단계에서 걸러서 **판정 행 자체가 필요 없어졌다** (삭제).

### 적재 단계의 한계

1. **문장 분할이 "- " 불릿 목록을 끊지 못한다.** 로수바스타틴 제산제의 근거가
   400자 약물 나열 덩어리다. 안에 "혈장 농도가 약 50% 감소되었다"가 들어
   있어서 사실은 맞지만 사용자에게 보여줄 문장은 아니다. 고치려면
   `extract.sentences` 를 바꿔야 하는데, 그러면 `eval/labels.tsv` 의 문장과
   어긋나서 621건을 다시 라벨링해야 한다. 그래서 미뤘다.
2. **`riskLevel` 규칙의 정확도를 측정하지 않았다.** 어투 기반 규칙이고,
   평가셋에 riskLevel 라벨을 추가하면 측정할 수 있다. 그때까지 기본값은
   보수적으로 `caution` 이다.
3. **라벨러·리뷰어가 1명이고 규칙을 쓴 사람과 같다.**
4. **성분 매칭이 이름 문자열 일치다.** `INGREDIENT_ALIAS` 로 아스피린→
   아세틸살리실산, 와파린→와파린/와파린 나트륨만 처리했다. 표본을 넓히면
   `MAIN_ITEM_INGR` 의 성분 코드로 붙이는 쪽이 맞다. 식약처 표기가 seed 와
   다른 성분도 있다 — 서트랄린의 식약처 표준명은 **설트랄린**이고,
   `서트랄린`으로 조회하면 0건이다 (`sample_docs.SEARCH_NAME`).
5. **`pick` 이 최대 181자까지 길어졌다.** 시프로플록사신 제산제 문장은 두
   제조사 버전이 180자까지 같고 끝에서만 갈린다. 핀이 유일해지려면 그만큼
   길어야 한다. 데이터 파일이라 비용은 없지만 보기 좋지는 않다.

## 표기 변형: "비타민 K"

범주↔개별 식품 매핑을 하려다 **매핑할 범주 행이 없다**는 것을 먼저 발견했다.
손으로 적은 42행 중 와파린 쪽 9행(시금치·케일·브로콜리·양배추·청국장·콩가루·
김치·녹차)은 전부 비타민K 때문인데, 적재된 행에 `비타민K` 가 없었다.

원인은 표제어 매칭이다. 허가사항은 **"비타민 K"(공백 포함, 코퍼스에 407건)**
라고 쓰는데 `FOODS` 표제어는 `"비타민K"` 였다. `candidates()` 는
`re.escape(kw)` 로 정확히 맞춰 보므로 407건이 **한 번도 후보가 되지 못했다.**
`loose()`(어절 내 공백 허용)는 round 3 에서 추가했지만 **차단 사전에만** 쓰고
있었다.

### 공백을 전역으로 허용하면 안 된다 — 세어 봤다

`candidates()` 와 `real_hits()` 를 `loose()` 로 바꿔 보니 후보가
1,204 → 1,271 (+67) 로 늘었는데, **56건이 어절 경계를 넘은 쓰레기**였다.

| 잡힌 것 | 문장 | 건수 |
|---|---|---|
| 우유 | "경**우 유**지용량", "함**유 제**품" | 11 |
| 알코올 (와인) | "식이**와 인**슐린" | 7 |
| 알코올 (맥주) | "정**맥 주**사" | 5 |
| 소주 | "국**소 주**사" | 2 |
| 두유 | "모**두 유**의한" | 1 |
| 지방 | "까**지 방**사선" | 1 |

그래서 전역 허용을 되돌리고, **코퍼스에 공백 표기가 실제로 나오는 표제어만**
사전에 넣었다. 3글자 이상 표제어를 전부 세어 보니 둘뿐이다.

    "비타민 K": "비타민K"            407건
    "세인트 존스 워트": "세인트존스워트"   97건

**사전이 규칙보다 안전한 자리가 있다.** 공백 허용은 규칙으로 쓰면 글자 수가
적은 한국어에서 어절 경계를 넘는다. 표제어 두 줄이면 끝나는 일이었다.

### 새 라벨 40건

후보가 40건 늘었다(양성 10). 회차가 아니라 어휘 확장분이라 `round=vocab` 으로

| 분류 | 건수 | 라벨 |
|---|---|---|
| "비타민 K 결핍증" (항생제 부작용) | 27 | 0 |
| "비타민 K 1 을 정맥주사" (해독 처치) | 3 | 0 |

  있는데 구조가 같아서 함께 걸렸다 — test 를 보고 고친 것이 아니다.

- `야채` 에는 **안 붙였다.** 와파린은 같은 문장에서 야채와 비타민K 를 둘 다 뽑아
  두 행이 나란히 뜨는데, 양쪽에 대표 식품을 달면 같은 목록이 두 번 보인다.
- `칼슘`·`철분`·`제산제` 에도 **안 붙였다.** 그 행들의 근거 문장은 "칼슘제제",
  "철분제제"처럼 **제제(약물)** 를 말한다. 우유·치즈를 대표 식품으로 달면
  보여주는 문장과 어긋난다. 범주라고 다 같은 범주가 아니다.

## 데이터 출처 메모

- **식약처 DUR 품목정보** — 병용금기·특정연령대금기·임부금기 등. **약물-약물** 상호작용이고 음식 항목이 없다.
- **의약품 제품 허가정보** — 위에서 확인한 대로 약-음식 정보가 주의사항 텍스트에 문장으로 들어 있다.
- **식품영양성분DB** — 음식 쪽 마스터 데이터.

## API 동작 메모

- `totalCount` 가 0 이면 `body` 에 `items` 키가 **아예 없다**. 빈 배열이 아니다.
- 성분명으로 `item_name` 조회가 안 되는 경우가 있다. 아세틸살리실산 → 0건
  (국내 제품명이 "아스피린"이라 성분명이 제품명에 없다).
- 같은 쿼리가 간헐적으로 60초 타임아웃된다. `sample_docs.collect` 는 받은 성분을
  건너뛰므로 재실행하면 못 받은 것만 다시 받는다 (재시도가 할당량을 태우면 안 된다).
