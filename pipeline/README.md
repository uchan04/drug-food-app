# pipeline

약-음식 상호작용 데이터를 공공데이터에서 받아 DB에 넣는 단계. 파이썬, 의존성 없음(표준 라이브러리만).

`apps/api/prisma/seed.ts` 의 상호작용 72행은 손으로 적은 것이고 출처가 없다.
DB에서 `source = 'seed:manual'` 로 표시된다. 이 디렉토리의 목적은 그 행들을
출처가 있는 데이터로 교체하는 것이다.

## 인증키

[공공데이터포털](https://www.data.go.kr) 에서 활용 신청 후 받은 **일반 인증키(Decoding)** 를 환경변수로 넣는다.

```sh
export DATA_GO_KR_KEY='발급받은_키'
```

Encoding 키를 넣으면 `urlencode` 가 한 번 더 인코딩해서 인증 실패한다. Decoding 키를 쓴다.

## 실행

```sh
python3 fetch.py <데이터셋이름> <엔드포인트URL> [추가파라미터=값 ...]
python3 test_fetch.py   # 자체 점검
```

받은 원본은 `data/raw/<데이터셋>/<수집시각>/` 에 페이지별로 그대로 저장되고,
같은 디렉토리의 `manifest.json` 에 URL·파라미터(키는 마스킹)·수집시각·페이지별 sha256 이 남는다.

**원본을 고치지 않는다.** 전처리를 수정할 때마다 API를 다시 때리면 재현이 안 되고,
"그때 받은 데이터가 지금과 다르다"를 증명할 수 없다. 원본은 읽기 전용으로 두고 다음 단계가 복사해서 쓴다.

## 확인된 API 계약 (의약품 제품 허가정보)

```
https://apis.data.go.kr/1471000/DrugPrdtPrmsnInfoService08/getDrugPrdtPrmsnDtlInq08
```

실제로 호출해서 확인한 사항이다. 추측이 아니다.

| 항목 | 값 | 비고 |
|---|---|---|
| JSON 플래그 | `type=json` | **`_type=json` 을 보내면 조용히 XML 이 온다** |
| 전체 건수 | 42,713 품목 | 허가일 오름차순(1957년부터) |
| 행 배열 | `body.items` 평면 배열 | `items.item` 중첩이 아니다 |
| 이름 필터 | `item_name=<제품명>` | 부분일치. 탐색에 쓸 수 있다 |
| 한 건 크기 | 약 8~40KB | 주의사항 XML 이 대부분 |

전체를 받으면 약 360MB, `numOfRows=100` 기준 약 430회 호출이다.
개발계정 한도가 1,000회/일이므로 한 번에 받을 수 있지만, 탐색 중에는
`--pages` 로 반드시 끊는다.

### 쓸 만한 필드

| 필드 | 내용 | 용도 |
|---|---|---|
| `ITEM_SEQ` | 품목기준코드 | 기본키 |
| `ITEM_NAME` / `ITEM_ENG_NAME` | 제품명 한/영 | `Drug.nameKo` / `nameEn` |
| `MAIN_ITEM_INGR` | `[M089710]심바스타틴` | `DrugIngredient` (코드+이름) |
| `MAIN_INGR_ENG` | `Simvastatin` | 성분 영문명 |
| `ATC_CODE` | `B05BA03` | `Drug.category` 분류 근거 |
| `ETC_OTC_CODE` | 전문/일반의약품 | |
| `CANCEL_NAME` | 정상 / 취하 | **취하 품목을 걸러야 한다** |
| `NB_DOC_DATA` | 사용상의주의사항 | **약-음식 정보가 여기 있다** |
| `UD_DOC_DATA` | 용법용량 | 복용 시점(식전/식후) |

### 문서 필드 파싱

`*_DOC_DATA` 는 XML 안에 CDATA 로 HTML 이 들어 있는 두 겹 구조다.
`<[^>]*>` 로 한 번에 밀면 `<![CDATA[` 가 본문 첫 `>` 까지 삼켜서 내용이 사라진다
(심바스타틴 품목에서 37,146자 → 618자). `parse.doc_text` 가 두 단계로 벗긴다.
제대로 벗기면 20,716자가 나온다.

### 추출이 실제 과제인 이유

심바스타틴 허가사항에는 이런 문장이 있다.

> 16) 자몽주스: 자몽주스는 CYP3A4를 저해하는 1개 또는 그 이상의 성분을 함유하고 있어
> CYP3A4에 의해 대사되는 약물의 혈장 농도를 증가시킬 수 있다.

기전까지 들어 있는 제대로 된 약-음식 상호작용이다. 그런데 단순 키워드 검색은
오탐이 매우 많다. 같은 문서에서 실제로 걸린 것들:

| 키워드 | 걸린 문맥 | 판정 |
|---|---|---|
| 자몽 | 자몽주스는 CYP3A4를 저해 | **진짜** |
| 술 | 대수**술** 며칠 전과 | 오탐 (수술) |
| 칼슘 | **칼슘**채널차단제 | 오탐 (약물 분류) |
| 공복 | **공복**혈당 ≥5.6mmol/L | 오탐 (검사 수치) |
| 섭취 | 알코올을 **섭취**하였다 | 애매 (음식이지만 상호작용 서술 아님) |

즉 키워드 매칭은 베이스라인이고, 정밀도를 올리는 것이 이 프로젝트의 ML 과제다.
라벨링과 평가셋이 필요한 이유도 이것이다.

## 상호작용 문장 판정: 평가셋과 측정

### 파이프라인

```sh
python3 sample_docs.py     # 성분별 허가사항 표본 수집 -> data/docs.jsonl
python3 make_labelset.py   # 후보 생성 -> eval/candidates.tsv (라벨 칸 비어 있음)
python3 score.py           # eval/labels.tsv 로 지표 측정
python3 score.py --fp      # 남은 오탐 보기 (dev 만)
```

`sample_docs.py` 가 성분명으로 조회하는 이유는, 데이터셋 전체가 허가일
오름차순이라 앞 페이지가 1957년 주사액이기 때문이다. 경구약 주의사항이 필요하다.
성분당 1회 호출이므로 개발계정 한도(1,000회/일)에 거의 영향이 없다.

### 두 단계로 나눈 구조

| 단계 | 함수 | 담당 | 방식 |
|---|---|---|---|
| 1 | `extract.candidates` | 재현율 | 음식 사전 71표제어로 문장을 넓게 긁는다 |
| 2 | `extract.judge` | 정밀도 | 차단 사전 + 영향없음 패턴으로 후보를 걸러낸다 |

평가 단위는 **(문장, 음식)** 쌍이다. `Interaction` 이 (성분, 음식) 쌍이기 때문이다.

### 평가셋

- 23개 성분 × 상위 3품목 = **63개 허가사항 문서** (주의사항 중위 7,589자)
- 후보 805건 → (문장, 음식) 중복 제거 **379건**
- 손으로 라벨링: 양성 148 (39.1%), 음성 231
- `eval/labels.tsv` 에 문장을 그대로 담았다. **원본 데이터도 API 키도 없이 측정이 재현된다.**

양성 정의: 그 음식의 섭취가 약의 효과·흡수·안전성을 바꾼다고, 또는 약 때문에
그 음식 섭취를 제한·조정해야 한다고 서술하는 문장.

음성에 포함한 것:

- 키워드가 음식이 아님 (정맥주사, 콩팥, 콜레스티라민, 입술, 유당분해효소)
- 음식이지만 상호작용 서술이 아님 (검사 수치, 질환명, 제제 성분명)
- **상호작용이 "없다"고 명시한 문장** — 허가사항은 병용시험 음성 결과도 적는다. 앱은 위험만 보여주므로 적재 대상이 아니다
- **음식을 치료 수단으로 쓰는 문장** (과량투여 시 제산제 투여, 저혈당에 설탕 섭취)

### dev / test 분할

**성분 단위**로 나눈다. 문장 단위로 나누면 같은 주의사항 문구를 쓰는 제네릭들
때문에 거의 동일한 문장이 양쪽에 섞여 들어가 test 가 오염된다.
차단 사전과 영향없음 패턴은 **dev 오류만 보고** 고쳤고 test 는 손대지 않았다.

### 결과

| split | n | 양성 | 모델 | 정밀도 | 재현율 | F1 |
|---|---|---|---|---|---|---|
| dev | 172 | 60 | baseline | 0.349 | 1.000 | 0.517 |
| dev | 172 | 60 | **rules** | **0.833** | **1.000** | **0.909** |
| test | 207 | 88 | baseline | 0.425 | 1.000 | 0.597 |
| test | 207 | 88 | **rules** | **0.822** | **1.000** | **0.903** |

- 베이스라인(키워드 있으면 양성) 정밀도가 0.4 수준이다. 그냥 쓰면 **의료 정보의 60%가 틀린다.**
- 규칙으로 test 정밀도 0.425 → 0.822. 재현율은 1.000 그대로, 양성을 하나도 죽이지 않았다.
- test(0.822)가 dev(0.833)를 거의 그대로 따라간다. 사전이 dev 에만 맞춰진 게 아니라는 뜻이다.

`score.py --check` 가 하한(정밀도 0.78 / 재현율 0.98)을 지킨다. CI 에서 돌아간다.

### 베이스라인을 죽인 오탐들

전부 63개 문서에서 실제로 센 것이다. 추측이 아니다.

| 키워드 | 등장 | 실제 정체 | 진짜 |
|---|---|---|---|
| 차 | 322 | 차단제, 자동차, 차이, 점차 | 0 → 사전에서 제외 |
| 술 | 144 | 수술, 시술, 기술, **입술**, 우회로술 | ~11 |
| 나트륨 | 129 | 성분 염 이름 (와파린나트륨) | 0 → 사전에서 제외 |
| 칼슘 | 105 | 칼슘채널차단제, 저칼슘혈증, 탄산칼슘 | 일부 |
| 공복 | 59 | 공복**혈당** (검사 수치) | 일부 |
| 맥주 | 58 | **정맥주사** | 0 |
| 콩 | 40 | **콩팥** (신장) | 0 |
| 당분 | 31 | **유당분해효소** | 0 |
| 지방 | 27 | 중성지방, 지방간, 고지방혈증 | 1 |
| 섬유 | 20 | 섬유증, 신경 섬유 | 0 |
| 티라민 | 7 | **콜레스티라민** (약물) | 0 |
| 소주 | 1 | **국소주사** | 0 |

차단은 문장 단위가 아니라 **등장 위치 단위**로 한다. "수술 전에는 술을 마시지
않도록 한다" 처럼 노이즈와 진짜가 한 문장에 있으면 진짜가 살아야 한다.

### 남은 한계

1. **재현율의 상한.** 재현율 1.000은 1단계가 만든 후보 풀 안에서의 값이다.
   음식 사전에 전혀 걸리지 않는 문장은 측정 범위 밖이다. 문서 전체를 라벨링해야
   실제 재현율이 나온다.
2. **남은 오탐 31건은 거의 전부 "음식을 치료 수단으로 쓰는 문장"** 이다.
   규칙으로 쓰면 브리틀해진다. 여기부터가 분류 모델의 몫이다.
3. **라벨러가 1명이고, 규칙을 쓴 사람과 같다.** 라벨은 규칙보다 먼저 붙였지만
   편향이 없다고 할 수는 없다.
4. **원본 데이터에 오타가 있다.** test 오탐 중 `칼슘체널저해제`(채널→체널)가 있다.
   test 를 보고 사전에 넣으면 측정이 거짓이 되므로 넣지 않았다.
5. 표본이 23개 성분이다. 전체 42,713품목으로 넓히면 사전에 없는 음식이 나온다.

## 데이터 출처 메모

- **식약처 DUR 품목정보** — 병용금기·특정연령대금기·임부금기 등. **약물-약물** 상호작용이고 음식 항목이 없다.
- **의약품 제품 허가정보** — 위에서 확인한 대로 약-음식 정보가 주의사항 텍스트에 문장으로 들어 있다.
- **식품영양성분DB** — 음식 쪽 마스터 데이터.

## API 동작 메모

- `totalCount` 가 0 이면 `body` 에 `items` 키가 **아예 없다**. 빈 배열이 아니다.
- 성분명으로 `item_name` 조회가 안 되는 경우가 있다. 아세틸살리실산 → 0건
  (국내 제품명이 "아스피린"이라 성분명이 제품명에 없다).
- 같은 쿼리가 간헐적으로 60초 타임아웃된다. `sample_docs.collect` 는 받은 성분을
  건너뛰므로 재실행하면 못 받은 것만 다시 받는다 (재시도가 할당량을 태우면 안 된다).

## 아직 쓰지 않은 것

`normalize.py`, `load.py`. 판정 기준이 위에서 정해졌으므로 이제 쓸 수 있다.
적재할 때 `Interaction.source` 는 `mfds:permit:<ITEM_SEQ>`, `sourceUrl` 은
엔드포인트, `fetchedAt` 은 manifest 의 `fetched_at` 을 쓴다.
