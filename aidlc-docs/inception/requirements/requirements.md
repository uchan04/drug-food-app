# Requirements Document

| 항목 | 내용 |
|------|------|
| **사용자 요청** | 약-음식 상호작용 체크 웹 애플리케이션 |

## 1. 기능 요구사항 (Functional Requirements)

### FR-01: 약물 검색

| 항목 | 내용 |
|------|------|
| **설명** | 사용자가 제품명 또는 성분명으로 약물을 검색할 수 있다 |
| **우선순위** | 필수 (MVP) |

- 제품명 검색 (예: 아스피린, 타이레놀)
- 성분명 검색 (예: 아세트아미노펜, 이부프로펜)
- 자동완성/추천 검색어 지원
- 검색 결과에 약물 분류, 성분 정보 표시

### FR-02: 내 약상자 (My Medicine Box)

| 항목 | 내용 |
|------|------|
| **설명** | 사용자가 현재 복용 중인 약을 등록/관리할 수 있다 |
| **우선순위** | 필수 (MVP) |

- 검색된 약물을 '내 약상자'에 추가
- 약상자에서 약물 제거
- 약상자 목록 조회
- 사용자 계정에 약상자 데이터 영구 저장

### FR-03: 약-음식 상성 분석

| 항목 | 내용 |
|------|------|
| **설명** | 등록된 약물의 성분과 음식 데이터를 매칭하여 상호작용 분석 |
| **우선순위** | 필수 (MVP) |

- 약상자에 등록된 약물 기반 자동 분석
- 개별 약물 선택 시 즉시 분석 가능
- 분석 결과를 Risk Level 3단계로 구분:
  - **주의 (Caution)**: 가벼운 상호작용, 주의하면 됨
  - **경고 (Warning)**: 의미 있는 상호작용, 시간 간격 필요
  - **금기 (Contraindicated)**: 함께 섭취 금지

### FR-04: 상성 결과 리포트

| 항목 | 내용 |
|------|------|
| **설명** | 분석 결과를 시각적으로 구분된 리포트 형태로 표시 |
| **우선순위** | 필수 (MVP) |

- 위험도별 색상 구분 (주의: 노랑, 경고: 주황, 금기: 빨강)
- 피해야 할 음식 목록 표시
- 상호작용 원리 요약 표시

### FR-05: 상세 가이드

| 항목 | 내용 |
|------|------|
| **설명** | 상호작용에 대한 상세 설명과 실용적 팁 제공 |
| **우선순위** | 높음 (Post-MVP) |

- "왜 같이 먹으면 안 되는지" 상호작용 이유 설명
- 예상 부작용 상세 설명
- "얼마나 시간 간격을 두어야 하는지" 팁 제공
- 대체 음식 추천 (가능한 경우)

### FR-06: 사용자 인증

| 항목 | 내용 |
|------|------|
| **설명** | 이메일/비밀번호 및 소셜 로그인을 통한 계정 관리 |
| **우선순위** | 필수 (MVP) |

- 이메일/비밀번호 회원가입
- 소셜 로그인 (Google, Kakao)
- 비밀번호 재설정
- 계정 정보 수정
- 로그아웃

### FR-07: 다국어 지원

| 항목 | 내용 |
|------|------|
| **설명** | 한국어 및 영어 UI 지원 |
| **우선순위** | 높음 (MVP 포함) |

- 한국어 기본 언어
- 영어 전환 가능
- 약물/음식 데이터도 이중 언어 지원

## 2. 비기능 요구사항 (Non-Functional Requirements)

### NFR-01: 성능

- 검색 응답 시간: < 500ms
- 상성 분석 응답 시간: < 1초
- 페이지 초기 로딩: < 3초
- 동시 사용자 100명 이상 지원

### NFR-02: 가용성

- SLA 목표: 99.5% (월간)
- RTO: 시간 단위 (Backup & Restore 전략)
- RPO: 시간 단위 (일일 백업)

### NFR-03: 확장성

- 수평 확장 가능한 아키텍처
- 약물/음식 데이터 증가에 대응 가능한 DB 설계

### NFR-04: 유지보수성

- 약-음식 상성 데이터 추가/수정이 용이한 구조
- 관리자용 데이터 관리 인터페이스 (Post-MVP)

### NFR-05: 접근성

- WCAG 2.1 AA 수준 준수
- 반응형 디자인 (모바일 브라우저 호환)

## 3. 기술 스택 결정

| 계층 | 기술 |
|------|------|
| **프론트엔드** | React (Next.js) |
| **백엔드** | Node.js (NestJS) |
| **데이터베이스** | PostgreSQL (자체 구축) |
| **인증** | JWT + OAuth 2.0 (Google, Kakao) |
| **배포** | Vercel (프론트) + AWS (백엔드) — AI-DLC 추천 |
| **CI/CD** | GitHub Actions |
| **테스트 (PBT)** | fast-check (TypeScript PBT 프레임워크) |

### 배포 환경 추천 근거

사용자가 배포 환경 선호 없음(D)을 선택하여 AI-DLC가 추천합니다:
- **프론트엔드**: Vercel — Next.js 네이티브 지원, 자동 CDN, 간편 배포
- **백엔드**: AWS (ECS Fargate 또는 Lambda) — 비용 효율적, 확장 용이
- **데이터베이스**: AWS RDS PostgreSQL — 자동 백업, 멀티 AZ 지원

## 4. 약-음식 상성 데이터베이스 설계

### 핵심 데이터 카테고리

| 약물 분류 | 성분 예시 | 피해야 할 음식 | 상호작용 원리 | 위험도 |
|-----------|-----------|---------------|---------------|--------|
| 고혈압약 (ACE 억제제) | 리시노프릴, 에날라프릴 | 바나나, 자몽, 오렌지 | 칼륨 배출 억제 → 고칼륨혈증 | 경고 |
| 고지혈증약 (스타틴) | 아토르바스타틴 | 자몽, 자몽주스 | CYP3A4 억제 → 약물 농도 상승 | 금기 |
| 항생제 (테트라사이클린) | 테트라사이클린, 독시사이클린 | 우유, 치즈, 제산제 | 칼슘/마그네슘 결합 → 흡수 방해 | 경고 |
| 진통소염제 (NSAIDs) | 이부프로펜, 아스피린 | 알코올, 커피 | 위 점막 자극 → 위장 출혈 위험 | 금기 |
| 통풍약 | 알로푸리놀 | 맥주, 고푸린 음식 | 요산 수치 상승 → 약효 감소 | 경고 |
| 항응고제 | 와파린 | 시금치, 케일, 콩가루 | 비타민 K → 혈액 응고 촉진 | 금기 |

### 데이터 모델 개요

- **drugs** 테이블: 약물 정보 (제품명, 성분명, 분류)
- **foods** 테이블: 음식 정보 (음식명, 주요 성분/영양소)
- **interactions** 테이블: 상호작용 정보 (약물-음식 매핑, 위험도, 설명)
- **users** 테이블: 사용자 정보
- **medicine_boxes** 테이블: 사용자별 약상자

## 5. 복원력 (Resiliency) 요구사항

### 5.1 DR 전략

- **전략**: Backup & Restore (RPO/RTO: 시간 단위)
- **비용**: 최저 ($)
- **적합성**: MVP 단계 비핵심 워크로드로 적절

### 5.2 변경 관리

- **프로세스**: AI-DLC 제안 경량 프로세스
  - 변경 기록 (PR description에 기록)
  - 승인 (PR review)
  - 롤백 노트 (배포 시 이전 버전 태그 기록)

### 5.3 CI/CD 및 배포

- **CI/CD**: GitHub Actions
- **롤백**: 이전 IaC/아티팩트 버전 재배포 (버전 고정)
- **배포 전략**: Direct / in-place
- **근거**: MVP 단계에서 비용 최소화, 복잡도 낮춤

### 5.4 인시던트 대응

- **프로세스**: AI-DLC 제안 경량 프로세스
  - 알림 → 확인 → 대응 → 복구 → COE 작성
  - 간단한 인시던트 템플릿 제공
  - Slack/Discord 기반 알림 (추후 구성)

## 6. 테스트 전략 (Property-Based Testing)

### 6.1 PBT 프레임워크

- **프레임워크**: fast-check (TypeScript)
- **통합**: Jest/Vitest 테스트 러너와 연동
- **시드 기록**: CI에서 모든 PBT 실행 시 시드 로깅

### 6.2 예상 PBT 적용 영역

- 약물 검색 로직 (검색어 정규화 round-trip)
- 상성 분석 엔진 (위험도 분류 invariant)
- 데이터 직렬화/역직렬화 (round-trip)
- 약상자 상태 관리 (stateful property testing)

## 8. 제약 조건 및 가정

### 제약 조건
- 의료 면책 고지 필수 (서비스는 참고 정보 제공 목적, 의료 진단/처방 대체 불가)
- 약-음식 상성 데이터는 신뢰할 수 있는 약학 자료 기반으로 구축
- 개인정보보호법 준수 (이메일, 복용 약물 정보 보호)

### 가정
- 초기 데이터베이스는 한국 시판 주요 약물 100~200개 수준으로 시작
- 데이터 확장은 수동 입력 + 검증 프로세스를 통해 진행
- 사용자 규모: 초기 수백 명 → 점진적 확장
