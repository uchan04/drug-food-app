# tools

`node` 로 직접 돌리는 스크립트. 앱 빌드에는 포함되지 않는다
(`tsconfig.build.json` 의 `exclude`).

## 검색 품질 측정

```sh
pnpm --filter api eval:search            # 지표 + 1위 못 잡은 쿼리 목록
pnpm --filter api eval:search -- --check # 하한 미달이면 0 아닌 코드로 종료 (CI)
```

`DrugService.search` 와 `DrugService.autocomplete` 를 직접 호출한다. trigram
검색이 Postgres 안에 있어서 DB 없이는 측정할 수 없다. HTTP 대신 서비스를
직접 부르는 이유는 서버를 띄우지 않아도 되고 측정 대상이 검색 로직이기
때문이다.

### 평가셋

`search-queries.tsv` — 110개 쿼리, 커밋되어 있다. 유형별로 나눈 이유는 전체
평균만 보면 어느 입력에서 깨지는지 안 보이기 때문이다.

| 유형 | n | 예 |
|---|---|---|
| `product` | 26 | 타이레놀 → d009 |
| `ingredient` | 13 | 아세트아미노펜 → d009 (제품명과 다른 성분만) |
| `variant` | 22 | 타이레놀500, 리피토정 20밀리그램 |
| `typo` | 22 | 타이레올, 아세트아미토펜, 지르택 |
| `product_en` | 16 | Tylenol → d009 (`lang=en`) |
| `ingredient_en` | 11 | Acetaminophen → d009 |

`expect` 는 쉼표로 여러 정답을 쓸 수 있다. 순위는 첫 정답의 1-based 위치다.

### 지표

| | 뜻 |
|---|---|
| R@1 | 정답이 1위인 비율 |
| R@5 | 정답이 5위 안인 비율 |
| MRR | 1/정답순위의 평균 |

**R@5 는 지금 코퍼스에서 쓸모가 없다.** 약이 26개뿐이라 상위 5개가 전체의
19%고, 정렬이 완전히 망가져 있을 때도 100%가 나왔다. 민감한 지표는 R@1 과
MRR 이다. 코퍼스가 42,713 품목으로 커지면 R@5 도 의미가 생긴다.

### 이 평가셋이 잡은 것

두 개의 랭킹 버그. 둘 다 tsc·lint·테스트를 전부 통과한 상태였다.

**1. `search()` 가 유사도 대신 약품 ID 순으로 정렬했다.**

`SELECT DISTINCT ON (d.id) ... ORDER BY d.id, similarity DESC`. `FROM` 절에
JOIN 이 없고 성분 매칭은 상관 스칼라 서브쿼리라서 약마다 행이 하나뿐이고,
`DISTINCT ON` 이 지울 중복이 애초에 없었다. 그런데 Postgres 는 `DISTINCT ON`
식을 `ORDER BY` 맨 앞에 요구하므로 `ORDER BY d.id` 가 강제되어 관련도 정렬이
깨졌다. `아세트아미노펜` 검색에 아스피린(d008)이 타이레놀(d009)보다 먼저
나왔다. 쓸모없는 방어 코드 한 줄이 검색 랭킹을 망가뜨린 것이다.

`DISTINCT ON` 을 지우고 `ORDER BY similarity DESC, d.id` 로 바꿨다. `d.id` 는
동점 처리용이다 — 전순서가 없으면 `OFFSET` 페이징에서 행이 중복되거나
누락된다.

**2. `autocomplete()` 가 약품 결과와 성분 결과를 유사도 없이 이어 붙였다.**

`아토르바스타틴` 을 정확히 입력해도 심바스타틴이 1위였다. 양쪽에서
`ceil(limit/2)` 씩만 받던 것도 함께 고쳤다 — 한쪽이 더 좋은 후보를 다 갖고
있어도 절반만 들어왔다. 제품명과 성분명이 같은 약(심바스타틴)이 두 번
제안되던 것도 이름으로 중복 제거했다.

### 측정값

| | 수정 전 | 수정 후 |
|---|---|---|
| `search` R@1 | 0.782 | **1.000** |
| `search` MRR | 0.879 | **1.000** |
| `autocomplete` R@1 | 0.936 | **1.000** |
| `autocomplete` MRR | 0.967 | **1.000** |

수정 전 1위를 놓친 24건은 **전부 결과가 약품 ID 오름차순**이었다
(`아세트아미노펜 → d008 d009`, `Sertraline → d005 d006 d013 d020 d021`).
1위를 맞춘 86건은 정답의 ID 가 우연히 가장 낮았던 경우다.

CI 하한은 R@1 0.95 / MRR 0.97 / autocomplete R@1 0.95 다. 측정값보다 낮게
잡아서 실제 퇴행만 걸린다. 하한을 넘겼을 때 종료 코드 1 로 죽는 것을
확인했다.

### 한계

1. **전 유형 100%는 평가셋이 26개 약품 코퍼스에 너무 쉽다는 뜻이다.** 지금
   이 평가셋의 가치는 절대 품질 측정이 아니라 퇴행 감시다.
2. **정답을 한 사람이 정했다.** 제품명·성분명·영문명은 seed 데이터에서
   기계적으로 나오지만, 오타와 용량 변형은 사람이 만든 것이다.
3. **오타가 한국어 음절 혼동 위주다** (ㅔ/ㅐ, 받침 누락, 자음 혼동).
   초성 검색(`ㅌㅇㄹㄴ`)이나 영타(`xkdlfpsnf`)는 없다. 둘 다 실제로 쓰이는
   입력이고, trigram 으로는 안 잡힌다.
4. **`0.1` / `0.15` 유사도 임계값을 측정으로 정하지 않았다.** 지금은
   재현율이 100%라 임계값을 내릴 이유가 없지만, 코퍼스가 커지면 임계값과
   `LIMIT` 의 상호작용이 드러난다.
